The best Claude Code history viewers for Mac in 2026

November 13, 2026 · Prices and features checked against each vendor's own site on this date

Claude Code keeps every session on your Mac as a JSONL file under ~/.claude/projects/, and deletes the old ones on a timer. These five apps turn those files into something you can read, search and resume.

They split into three kinds: viewers that read the files as they are, a monitor that watches live sessions and cost, and memory tools that index sessions alongside the rest of your work. We make L2Cache, which is in the third group; the others are all free open-source projects and worth knowing about.

2. Claude Code History Viewer: the widest coverage, free

A cross-platform Tauri app that reads around 30 coding agents' local history, from Claude Code and Codex CLI to Cursor, Cline, Aider and Gemini CLI. It shows sessions as trees with diffs, images and tool results, searches across every provider, and has a token and cost dashboard. Its one-click Full Backup archives every Claude Code session so nothing is lost to automatic cleanup. It also runs as a headless server you open in a browser.

Trade-offs: a reader: no resume, and nothing beyond agent sessions. Price: free, MIT licence.

3. Claudoscope: a live dashboard for heavy Claude Code users

A native menu bar app that watches ~/.claude/projects/ as sessions run. Its fleet view lists every session from the last 24 hours with the ones waiting on you first; a Trace tab replays a session on a timeline with tool calls, subagents, context fill and cumulative cost. It prices usage at Anthropic rates, can alert on four spending limits, scans transcripts for leaked secrets and checks your config against 85 lint rules. A claude --resume button opens any session again.

Trade-offs: Claude Code and Cowork only; needs macOS 14 on Apple Silicon. Price: free, MIT licence.

4. Sessions Viewer: several CLIs, plus their config

Reads Claude Code, Codex, Grok Build, Kimi Code, Pi, Antigravity CLI and opencode from their own folders and shows them in one project, session and conversation view, with thinking blocks, matched tool results and diffs. It resumes supported sessions in a built-in or external terminal, exports to Markdown, HTML or JSON, and manages skills, MCP servers and hooks for all seven agents in one panel.

Trade-offs: search covers titles and prompts rather than whole conversations. Price: free, MIT licence.

5. SpecStory: keep the history in the repo instead

SpecStory takes a different route: instead of reading Claude Code's files later, its CLI wraps the agent and saves each session as Markdown in .specstory/history/ inside the project. History is then versioned with git, survives Claude Code's cleanup, and is readable by teammates and future agents.

Trade-offs: only captures sessions you run through it, and you browse Markdown files rather than an app. Price: free.

FAQ

Where does Claude Code store its history?

Claude Code saves each session as a JSONL file under ~/.claude/projects/, in a folder named after the project path. Each line is one event: a prompt, a reply, a tool call or a tool result.

Does Claude Code delete old sessions?

Yes. Claude Code removes old transcripts automatically after a retention period you can change with the cleanupPeriodDays setting. If you want to keep history, raise that setting or use a tool that keeps its own copy, such as Claude Code History Viewer's backup or L2Cache's local index.

How do I resume an old Claude Code session?

Run claude --resume with the session ID from the project directory, or claude --resume on its own to pick from a list. L2Cache, Claudoscope and Sessions Viewer can open the resume command for you from the session you found.
