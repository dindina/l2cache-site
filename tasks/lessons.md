# Lessons

- Before creating a new SEO landing page, check whether an existing URL already ranks for that query. If it does, improve that page and avoid publishing a second URL with overlapping search intent.

## Only pitch what the user chose to build (2026-11-03)
- Mistake: added "Team memory" to the Teams waitlist mockups from a *Proposed* PRD, and labelled it "Mac app: …" as if it existed.
- Rule: every feature on a marketing page or mockup must be (a) explicitly in the user's scope and (b) labelled with its real status. Check PRD **Status:** before writing "Basis: Mac app".
- Brainstorm ideas stay in chat until the user confirms them for the product.

## Never cite mockup data as evidence (2026-11-03)
- Mistake: quoted "cold reloads ≈ 2.4% of tokens" in a business assessment; it came from fictional mockup numbers I invented, and used token share instead of cost share.
- Rule: label every number by source (measured / external with link / invented example). Invented example numbers never appear in analysis or advice.
- Rule: for spend arguments, weight tokens by price (cache read ≈0.1×, cache write 1.25–2×, output ≈5× input) before giving percentages.
