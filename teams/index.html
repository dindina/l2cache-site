The problem

Agents made coding faster. Nobody can see what the sessions cost.

≈20×

Cold restarts cost the most

Resume a big session after its cache expired and the next message re-writes the whole context, about 20 times the cost of reading it from a warm cache. Nothing tells you it happened.

Tokens ≠ work

Usage without outcomes

Vendor dashboards count usage per tool. They don't show which sessions became commits, which ones stalled, or what was wasted.

Day 2

Context gets lost

After a /clear, a new day or a hand-over to a teammate, the agent starts over and work gets redone.

How we got ≈20×

On Anthropic's published prices, writing context into a 1-hour prompt cache costs 2× the model's base input price per token, and reading it back from a warm cache costs 0.1×. A cold resume re-writes the whole context instead of reading it: 2 ÷ 0.1 = 20× for that context. With a 5-minute cache the write costs 1.25×, so 12.5×.

This compares the cost of the reloaded context only. The new message and the reply cost the same either way, so the whole turn costs less than 20× more; for a large context the reload dominates.

Measured on one heavy user's Claude Code sessions over 30 days: cold reloads were 0.9% of tokens but about 10% of the estimated cost. Your team's share will differ; the report measures it.

Cold Resume Guard: stops the expensive message, once

Proactive session intelligence

Catches session problems before the developer notices.

The collector follows each session on the developer's machine while it runs. When it spots a problem, the suggested next step appears in the terminal, before the expensive or wasted turn.

When it detectsIt suggests
A big session is resumed after its cache expiredStart fresh with a handoff, or continue knowing what it costs
The session's context crosses a heavy thresholdCompact, or /clear and continue from a handoff
Unfinished work when a session is cleared or compactedWrite a handoff: done, pending and the last exchange
An error the team already fixed appears againReuse the team's fix: cause, files and the test that proved it
The session's goal has changed significantlyPlannedStart a fresh session for the new task
The same files are investigated again and againPlannedBring back what earlier sessions found
Context keeps growing with no edits or commitsPlannedReview the approach, or hand off

FAQ

Questions teams ask.

Do you read our developers' conversations?

No. The collector reads agent transcripts on each developer's own machine to work out session size, cache state and recaps. Prompts, replies, code and diffs are never uploaded. The team view receives numbers, commit SHAs, and the recaps and fixes each developer approves.

How does this relate to L2Cache?

It's a separate product from the makers of L2Cache, the Mac app for developer memory. It covers agent sessions only: no clipboard, screenshots or snippets. Several of the developer features already run in the L2Cache Mac app, and the screenshots for them are from it; they're being rebuilt to run on every platform. The team features are being built new.

Which agents does it support?

Claude Code and Codex first. Tell us in the form which other agents your team uses; that decides what comes next.

Does it work on Windows and Linux?

The collector and the local web app are being built to run on macOS, Windows (including WSL) and Linux. macOS comes first.

Does it work with Claude subscriptions as well as API keys?

Yes. Usage is read from the agent's own session files, so subscription seats are included. They're shown as tokens and quota; API-billed seats also get an estimated cost.

Can managers see individual developers?

By default, admins see per-developer usage numbers, never conversations. A team setting switches the report to team totals only.

How much will it cost?

Pricing will be per developer per month and announced before launch. Teams on the waitlist hear first.
